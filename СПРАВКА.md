# Справка по сайту

Как всё устроено и что делать в типичных случаях. Коротко, по делу, на русском —
в отличие от `README.md`, который написан для тех, кто придёт в репозиторий со стороны.

---

## 1. Что где лежит

| Адрес | Файл | Что это |
|---|---|---|
| `sanelabs.org/` | `index.html` | Лаборатория: линейка моделей, Sane Studio, контакты |
| `sanelabs.org/synth-2/` | `synth-2/index.html` | Synth-2: чем занята модель и живой лог обучения |

Плюс служебное:

```
run-log.json          запасная копия лога обучения
append_run_point.py   дописывает в неё одну точку
CNAME                 домен sanelabs.org, читается самим GitHub
README.md             то же самое по-английски, для посторонних
```

Каждая страница — **один файл**: разметка, стили и скрипты вместе. Сборки нет,
зависимостей нет. Правишь файл, коммитишь, пушишь — через минуту-две live.

Страницы ничего друг у друга не берут, поэтому одну можно ломать, не трогая вторую.

---

## 2. Обновить цифры обучения

Это то, что придётся делать чаще всего.

### Быстрый путь: SQL в Supabase

Проект **`synth-2-site`** → SQL Editor → выполнить:

```sql
insert into public.run_log (step, loss, recorded_on, note)
values (86000, 2.0290, '2026-09-12', 'первая сессия после починки router_bias')
on conflict (step) do update
  set loss = excluded.loss,
      recorded_on = excluded.recorded_on,
      note = excluded.note;
```

Сайт подхватит при следующей загрузке страницы. Ни коммитить, ни пересобирать не надо.

Необязательные поля той же таблицы:

- `trend_per_1k` — наклон на тысячу шагов, если он **померен** (не считай его по двум
  точкам, страница честно подпишет, откуда число);
- `trend_note` — как померен, например `МНК по 17 замерам`;
- `lr_event` — подпись вертикальной метки на графике, например `LR / 3`.

Цифры, которые не привязаны к шагу, живут в `run_meta` — там одна строка с `id = 'run'`:

```sql
update public.run_meta
   set expert_share = 24.1,   -- доля выхода FFN от маршрутизируемых экспертов
       mfu = 6.4,
       checkpoint_gb = 9.3,
       stage = 'B',
       updated_at = now()
 where id = 'run';
```

### Автоматически, из ноутбука

В `kaggle_tpu.ipynb` есть **ячейка 8**: после чистого прогона она сама дописывает
последний замер. Молчит и ничего не пишет, если прогон вернул ненулевой код, если
сессия встала на памяти или на квоте Hub, или если отложенный лосс мерился меньше
двух раз.

Чтобы работало, нужно один раз:

1. В Supabase → Project Settings → API keys скопировать **секретный** ключ
   (публикуемый со страницы не годится, он умеет только читать);
2. На Kaggle → Add-ons → Secrets добавить секрет с именем `SUPABASE_WRITE_KEY`;
3. Переимпортировать ноутбук на Kaggle — там лежит отдельная копия, из репозитория
   она не обновляется.

### Запасной файл

`run-log.json` — то же самое на случай, если Supabase недоступен. Раз в несколько
сессий его стоит подтягивать, чтобы не отставал:

```bash
python append_run_point.py --step 86000 --loss 2.0290 --note "что изменилось"
git add run-log.json && git commit -m "run log: step 86,000" && git push
```

### Откуда именно сейчас читаются числа

Страница берёт первый источник, который ответил: **Supabase → `run-log.json` →
хранилище артефакта**. Какой сработал, написано прямо в шапке панели — `live database`,
`run-log.json` или `artifact store`. Если видишь не то, что ожидал, значит предыдущий
источник не ответил.

## 3. Поправить текст на странице

Открыть нужный файл, найти текст, поменять, закоммитить. Всё в одном файле, искать
удобно по фразе.

```bash
git add -A && git commit -m "что поменял" && git push
```

GitHub Pages пересоберётся сам за минуту-две. Проверить, что выехало:

```bash
curl -s https://sanelabs.org/ | grep -o "<title>[^<]*</title>"
```

**Важно про правду.** На страницах намеренно нет ни одного числа, которое не померено.
Демо в шапке Synth-2 подписано как макет, потому что модель ещё учится и нигде не
запущена. Критерии приёмки подписаны как цели, а не результаты. Если добавляешь число —
добавляй вместе с тем, откуда оно взялось. Это единственное, что отличает страницу
от рекламы.

## 4. Посмотреть локально перед пушем

```bash
python -m http.server 8000
```

Открыть `http://127.0.0.1:8000`. Просто открыть файл двойным щелчком тоже можно, но
тогда не подтянется `run-log.json` — браузер не разрешает запросы с `file://`.

## 5. Домен и хостинг

Домен `sanelabs.org` в **Hostinger**, DNS там же (NS `athena/apollo.dns-parking.com`).
Сайт отдаёт **GitHub Pages** из ветки `main`, корень репозитория.

Записи в зоне должны быть такие:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `185.199.108.153`, `.109`, `.110`, `.111` — все четыре |
| AAAA | `@` | `2606:50c0:8000::153`, `8001`, `8002`, `8003` |
| CNAME | `www` | `ssane-labs.github.io` |

Четыре A-записи — это не запасные варианты, а балансировка; с одной сайт держится
на единственной точке.

Файл `CNAME` в репозитории — то, чем GitHub понимает, что домен наш. **Не удаляй его**:
без него сайт вернётся на `ssane-labs.github.io`.

Сертификат выпускает GitHub сам (Let's Encrypt) и продлевает автоматически. Галка
**Enforce HTTPS** в Settings → Pages должна быть включена — тогда `http://` редиректит
на `https://`, а не отдаёт ошибку.

## 6. Если что-то сломалось

**Сайт отдаёт 404 на своём домене.** Проверь, что `CNAME` на месте и что в Settings →
Pages указан домен. Если DNS менялся — подожди, пока разойдётся зона.

**Открывается старая версия.** Pages кэширует. Проверь `curl` с параметром, например
`?v=2`, или просто подожди пару минут.

**`www` не открывается по HTTPS.** Значит CNAME для `www` указывает не на
`ssane-labs.github.io`, и GitHub не смог выписать на него сертификат.

**Числа на странице не те.** Посмотри, какой источник назван в шапке панели. Если
`run-log.json` — значит Supabase не ответил, и ты смотришь на запасную копию, которая
может отставать.

**Страница пустая или без стилей.** Скорее всего не загрузился CDN (GSAP, Lenis или
шрифты). Страница на этот случай сделана так, чтобы остаться читаемой без них —
если она всё-таки пустая, смотри консоль браузера.

---

## 7. Чего делать нельзя

- **Не клади секреты в этот репозиторий** — он публичный. Ключ Supabase, который лежит
  в `synth-2/index.html`, — *публикуемый*, он умеет только читать, на запись база
  отвечает `401`. Секретный ключ живёт только в секретах Kaggle.
- **Не убирай `overflow-x: clip`** и не меняй его на `hidden`: `hidden` делает `<body>`
  контейнером прокрутки, и страница перестаёт скроллиться.
- **Не выкидывай `<!DOCTYPE html>`** из начала файлов. Без него браузер уходит в
  quirks mode, и ломается сразу многое — от прокрутки до кодировки.
- **Не удаляй `CNAME`**.

## 8. Что ещё не доделано

- `sane-studio.ru` не работает: DNS смотрит на GitHub Pages, но сайт отдаёт 404 и
  сертификата нет. Скорее всего в том репозитории не настроен источник Pages.
- В бывшем публичном репозитории `ReedSeek` был закоммичен `.env` с `API_KEY`.
  Репозиторий закрыт, но ключ какое-то время лежал открыто — его надо **отозвать
  и выпустить заново**: то, что попало в публичную историю git, считается
  скомпрометированным.
